# 여행 준비 (TripReady) 프로젝트 규칙

여행 도시를 고르면 소개·명소·식당·항공권 검색을 자동으로 모아 보여 주고, 예산·준비 체크리스트·가고 싶은 곳을 여행별로 기록하는 웹앱. 수업 중간고사 과제이며 하루 안에 완성하는 것이 목표다.
작업 기준 문서는 **PRD.md(요구사항)** 와 **TODO.md(단계별 할 일)** 다. 세션을 시작하면 두 문서부터 읽는다.

- GitHub: https://github.com/hyeeun-hub/trip-ready (Public)
- 배포: https://hyeeun-hub.github.io/trip-ready/ (GitHub Actions, `.github/workflows/deploy.yml`)

## 기술 스택
React + TypeScript + Vite, 저장은 localStorage, 테스트는 Vitest, 배포는 GitHub Pages. (PRD #7)

- `npm test` 단위 테스트, `npm run build` 타입 검사 + 빌드, `npm run lint` 린트, `npm run dev` 개발 서버
- 외부 API는 **키 없이** 쓰는 위키백과 REST API, 오픈스트리트맵 Overpass·Nominatim만 쓴다.
- 새 라이브러리가 필요하면 **이유를 먼저 말하고 사용자 동의를 받은 뒤** 추가한다.

## 화면 구현
- 화면을 만들 때는 `.claude/design-notes.md`(사용자가 보낸 참고 이미지의 구성·분위기 메모)를 따른다. 디자인은 Todo 항목으로 따로 두지 않는다.
- 참고 이미지(`.claude/design-reference.jpg`)는 다른 서비스 화면이라 저장소에 올리지 않는다(.gitignore).

## 작업 규칙
- 0단계부터 순서대로 진행한다. 사용자 지시("내가 확인해야 하는 것만 빼고 알아서 진행해줘")에 따라, 단계가 끝나면 보고를 남기고 **커밋·push까지 한 뒤 다음 단계로 바로 넘어간다.**
- 멈추고 사용자에게 묻는 것: 새 라이브러리 추가, "만들지 않는 것"에 걸리는 기능, 되돌리기 어려운 작업, 사용자만 판단할 수 있는 것. 사용자의 브라우저 최종 확인 항목은 모아서 보고한다.
- 단계 보고에는 끝낸 Todo 번호, 테스트 결과, 사용자가 브라우저에서 직접 확인할 것, 계획과 달라진 점을 넣는다.
- Todo 항목은 **구현 → 테스트 통과 → 체크** 순서로만 완료 처리한다. 테스트를 통과하지 못했거나 확인하지 못한 항목은 체크하지 않는다.
- 브라우저 확인 항목은 Claude가 앱 내장 브라우저로 먼저 확인하고, 사용자가 최종 확인한다.
- 계획과 다르게 구현했거나, 항목을 추가·삭제했거나, 테스트 결과 때문에 바꾼 것이 있으면 **그 즉시** TODO.md 맨 아래 "Todo 변경 내역" 표에 날짜 없이 간략하게 한 줄 추가한다. 이유에는 "무엇을 보고 바꿨는지"를 쓴다.
- PRD의 "만들지 않는 것"에 있는 기능은 사용자가 요청하기 전에는 만들지 않는다.

## 커밋 규칙
- 형식: `<type>(<Todo 번호>): <무엇을 했는지 한국어로>`
  - type: feat, fix, test, docs, design, refactor, chore
  - 예: `feat(2-2~2-4): 위키백과 소개와 오픈스트리트맵 명소·식당 불러오기`
- 서로 관계없는 Todo를 한 커밋에 섞지 않는다. Todo 단계마다 커밋하고, 단계가 끝날 때마다 push한다.
- `git add -A`, `git add .` 대신 파일 이름을 지정해서 스테이징하고, 커밋 전 `git diff --cached --stat`으로 확인한다. 커밋 명령은 `&&`로 이어 실패하면 멈추게 한다.

## 외부 데이터 원칙
- 자동으로 가져온 정보에는 출처(위키백과, © OpenStreetMap 기여자)를 함께 표시한다.
- 앱이 사실(영업시간, 가격, 평점 등)을 지어내지 않는다. 데이터에 없는 값은 비워 둔다.
- 인기 도시 데이터(위키 문서명·좌표·공항 코드)는 기억으로 쓰지 않고 위키백과·위키데이터에서 확인한 값만 출처 URL과 함께 넣는다.
- 외부 API를 붙이거나 바꿀 때는 `external-api-check` 스킬 절차를 따른다.

## 프로젝트 스킬 (`.claude/skills/`)
- `todo-wrapup`: Todo 항목을 끝낼 때 사용 (테스트 → 체크 → 변경 내역 → 커밋 메시지 → 보고)
- `external-api-check`: 외부 API를 붙이거나 바꿀 때 사용 (이용 정책 → 출처 표시 → 고정 응답 테스트 → 실패 처리 → 실제 호출 확인)
- 스킬을 쓸 때마다 아래 "스킬 사용 기록"에 날짜 없이 한 줄 추가한다. README의 "스킬이 어떻게 쓰였는지"에 사용한다.

## README에 들어가야 할 것 (6단계)
제작한 것 소개 / PRD와 Todo 리스트 / Todo 변경 내역 / 사용한 스킬의 SKILL.md 내용, 작업에서 어떻게 쓰였는지, 직접 만든 이유 / 느낀 점, 결론
